# Состояние проекта и продолжение обучения

Состояние на 11 ноября 2026. Проект анализирует отзывы Wildberries и помогает продавцу найти частые
проблемы и отзывы, где нужен человек. Отдельной автономной генерации ответов в текущем продукте нет.

## Что исправлено после аудита

[Аудит данных и повторная проверка](../reports/data_audit.md): прежние метрики воспроизведены,
отдельно показана оценка без примеров-подсказок учителю. Для ручного эксперимента подготовлено
72 train / 24 development / 5 спорных в карантине. В development всего один положительный пример;
по такой выборке нельзя подтверждать устойчивое улучшение качества.

Интерфейс `python needs_reply_label.py` теперь читает актуальные JSON в `labeling/`. По умолчанию
открывается новая партия из 150 отзывов: предсказания и черновики модели не показываются. Необходимость
человека и 8 причин отмечаются независимо; есть флаг сомнения, продолжение разметки и резервные копии.
Исходные 101 метка сохранены. Локальная страница запускается на `127.0.0.1:7864`.

Для ручного дообучения добавлен отдельный `train_manual.py`. Он продолжает сохранённого WB-студента,
обучает need и причины, не использует отсутствующие ручные метки тональности и требует новый выходной каталог.
Спорные случаи из аудита и сомнительные метки исключаются из обучения без изменения исходного эталона.
Development-разбиение связано по товарам и нормализованным текстам. Это эксперимент для разработки,
а не независимый тест: старые ручные метки уже изучались при настройке модели.

```bash
# Только подготовка: не обучает и не заменяет текущие веса. Каталог должен быть новым.
python train_manual.py --output data/manual_runs/prepared-01 --prepare-only

# Явное экспериментальное обучение в ДРУГОЙ новый каталог, если оно нужно:
python train_manual.py --output data/manual_runs/experiment-01 --device cpu

# Слепая разметка новой партии:
python needs_reply_label.py
```

Голова тональности в ручном режиме заморожена, но общий энкодер меняется: предсказания тональности после
такого обучения тоже могут измениться. Новый эксперимент не становится основной моделью автоматически.
Реальное переобучение основных весов в рамках этой подготовки не запускалось.

Экспорт демо теперь сохраняет неподтверждённый результат в локальном
`data/demo_maternity/unreviewed_export.json`, а в публичных JSON и HTML скрывает темы и подтверждающие
цитаты до перепроверки. Числа по причинам, тональности и нужности ответа явно остаются предсказаниями модели.

## Что означают метрики студента

На тесте из 2 000 меток учителей need F1 = 0.674 при пороге 0.35, выбранном на валидации из 1 000 отзывов.
Для обучения использованы остальные 17 000. Товары между этими частями не пересекаются.

На 101 ручной метке при пороге 0.35: 10 лишних срабатываний, 3 пропуска, precision 38%, recall 67%, F1 0.48.
При исследованном пороге 0.85: 6 лишних, 3 пропуска, precision 50%, recall 67%, F1 0.57.
Положительных примеров всего 9: этой выборки недостаточно для устойчивых выводов. Порог 0.85 исследован
на тех же ручных метках; независимый тест для него ещё нужен. Оценки до и после проверки меток учителем
из `student_curve.md` и `student.md` относятся к разным версиям эталона и напрямую не показывают прирост качества.

Новая подборка состоит из 75 отзывов с need score от 0.85 и 75 с score от 0.3 до 0.85.
Она выбрана из 300 тыс. оценённых отзывов, максимум по два на товар. Это подборка для поиска ошибок,
а не случайный тест. Подсказки студента ставят need=true у 143 из 150 примеров и могут влиять на разметчика.

## Правила для следующего этапа

1. Сохранить текущие веса `data/student/model`, `data/student/results.json` и ручные метки перед изменениями.
2. Использовать обновлённый интерфейс разметки `labeling/*.json`: отдельно need и причины,
   включая `wb_logistics`, с возможностью отметить сомнение.
3. Разметить 150 отзывов вслепую, скрыв предсказания студента, звёзды и ответы продавца. Исходные
   подсказки сохранить отдельно для последующего сравнения. Причина проблемы сама по себе не означает need=true.
4. Разобрать расхождения и обновить [инструкцию](needs_reply.md). В частности, формулировка о запахе
   шире некоторых последующих ручных решений: не любой неприятный запах пользователь считал риском здоровью.
   Спорные случаи нужно согласовать до массовой переразметки.
5. До обучения выделить новые независимые ручные validation/test по товарам и проверить дубликаты текста.
   Метки, использованные для настройки порога или обучения, не считать новым независимым тестом.
6. Сравнить дообучение с сохранённой моделью по precision/recall, пропускам и лишним срабатываниям,
   отдельно по причинам. Подборку из 150 использовать как диагностическую; для оценки частот нужна случайная выборка.
7. Проверить темы и подтверждающие цитаты в демо, особенно отрицания и соответствие размера.

## Локальные данные и запуск

На машине разработки сохранены `data/wb.parquet`, `data/teacher/labels.jsonl`, `data/student/model`,
`data/student/results.json`, `models/wb_student` и исходный `../ru-review-sentiment/model`.
Они исключены из Git. Наличие папок и файлов проверено 10 ноября; повторная оценка весов в этот день не проводилась.

`python train_student.py` запускается из корня репозитория и повторно обучает студента по итоговым меткам
учителей. По умолчанию он инициализируется из `../ru-review-sentiment/model` и перезаписывает текущий результат.
Он **не дообучает модель на новых ручных метках**: они используются для оценки. Для такого дообучения
теперь используется отдельный `train_manual.py`. Режим `train_student.py --cpu-smoke` возвращается до сохранения
модели; прежнее предупреждение о перезаписи весов в этом режиме было неточным.

Скрипт также читает исторические версии ручных меток через `git show`; для его отчёта нужна история Git,
а не только архив исходников. Скачивание WB и обучение тональности описаны в [README](../README.md).
Gradio добавлен в зависимости интерфейса.

Для RX 7900 GRE прежние эксперименты использовали нативный PyTorch ROCm под Windows, а LLM-учителя —
llama.cpp Vulkan. Соблюдать очередь: одна крупная модель на GPU за раз. Старые логи и скрипты очередей
описывают прошлые запуски и не подтверждают наличие активного процесса сейчас.
