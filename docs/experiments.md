# Подробный обзор анализа отзывов Wildberries

Сервис для продавца на Wildberries: по отзывам на его товары показывает **сводку частых проблем** и выделяет
**отзывы, на которые стоит ответить человеку**. Автоответов нет — продавец отвечает сам, сервис только
подсказывает, где это важно.

Статус на 10 ноября 2026: этапы 1–3 готовы; для этапа 4 («нужен ответ человека») обучен студент на 20 тыс.
меток LLM-учителей и выполнена сверка со 101 ручной меткой пользователя. Следующий шаг — разметить новую
подборку из 150 отзывов и улучшить согласие с критериями пользователя. Названия групп проблем — черновик до утверждения.
Актуальное состояние, ограничения и порядок продолжения: [docs/project_status.md](../docs/project_status.md).
Модель тональности берётся из проекта
[sentiment-analysis-ru](https://github.com/savocheek/sentiment-analysis-ru) (ruBert-base, дистиллированная
из ruRoberta-large на отзывах Яндекс Карт) и дообучается на товарах.

## Данные

- **Wildberries:** [nyuuzyou/wb-feedbacks](https://huggingface.co/datasets/nyuuzyou/wb-feedbacks) (CC0): товар
  (nmId), оценка 1–5★, текст, ответ продавца. Берутся два шарда parquet-конвертации HF (~2.6 млн отзывов,
  ~320 МБ), не весь датасет (10 ГБ).
- **Независимый тест:** [ai-forever/ru-reviews-classification](https://huggingface.co/datasets/ai-forever/ru-reviews-classification)
  (RuReviews, Apache-2.0): отзывы на товары с тремя классами тональности, англоязычные отзывы убраны.

После очистки — 2.29 млн отзывов на 204 тыс. товаров. 84% отзывов позитивные (4–5★), нейтральных (3★) 6.6%.
Продавец ответил на 43.5% отзывов, и 64% этих ответов — дословно повторяющиеся шаблоны («Спасибо за отзыв!»).
Подробно: [reports/data_stats.md](../reports/data_stats.md).

**Сплиты по товарам.** Каждый товар (nmId) целиком лежит в одном сплите (80/10/10 по хэшу nmId). Так модель не
видит в обучении отзывов на товары из теста — иначе она запоминала бы сами товары, и оценка была бы завышена.

## Тональность на товарах (этап 2)

Ученик из исходного проекта дообучен на сбалансированной выборке WB-train: по 55 тыс. отзывов на класс, не больше
30 на товар. Остановка по macro-F1 на WB-val (0.719 → 0.761, лучшая точка — 1.5 эпохи, 24 мин). Тест открыт один
раз. PyTorch и ONNX int8 оценены на одних и тех же наборах ([reports/eval.md](../reports/eval.md)):

| Модель | WB-test, все 221 тыс. | WB-test, сбаланс. 30k | RuReviews (независимый) |
|---|---|---|---|
| исходный ученик (base) | 0.610 | 0.718 | 0.736 |
| исходный ученик, ONNX int8 | 0.607 | 0.715 | 0.733 |
| исходный учитель (large) | 0.609 | 0.720 | 0.740 |
| **WB-ученик** | **0.663** | **0.763** | **0.765** |
| **WB-ученик, ONNX int8** (171 МБ) | **0.663** | **0.762** | **0.762** |

Дообучение на товарах дало +0.05 macro-F1 на WB и +0.03 на независимом RuReviews. int8 почти не теряет качества.
Слабое место — нейтральный класс (3★): F1 0.37 на полном тесте, где таких отзывов всего 7%, и 0.67 на
сбалансированной выборке. Звезда 3★ на WB часто ставится за «нормально, но…», и текст мало отличается от 4★.

## Частые проблемы покупателей (этап 3)

1. **Жалобы.** Источники — отзывы WB-train на 1–3★ и отзывы на 4–5★ с поворотом («но», «минус», «жаль», «брак»…).
   Отзывы нарезаются на фразы, и остаются только фразы, которые WB-ученик считает уверенно негативными
   ([complaints.py](../complaints.py)). После дедупликации получилось 920 тыс. уникальных фраз, 1.2 млн упоминаний.
2. **Эмбеддинги и группы** ([topics.py](../topics.py)): энкодер [sergeyzh/rubert-mini-frida](https://huggingface.co/sergeyzh/rubert-mini-frida)
   (MIT) и KMeans на 40 групп. Выбор сделан на пробе из 10 тыс. фраз ([reports/topics_probe.md](../reports/topics_probe.md)):
   frida в 11 раз быстрее deepvk/USER-base и лучше согласуется с грубыми группами по ключевым словам
   (NMI 0.53 против 0.48). HDBSCAN отправил в шум 90% фраз.
3. **Отчёт** [reports/topics.md](../reports/topics.md). Для каждой группы: ключевые слова (c-TF-IDF), 5 типичных фраз,
   доля жалоб, распределение по звёздам. Названия групп — **черновик**, их нужно утвердить, объединить похожие
   группы или выбросить мусор на странице `python topics_label.py` (порт 7863). Каждое решение сохраняется сразу.
   Примерно 7 групп из 40 — обрывки фраз и мусор. Их стоит выбросить при разметке.
4. **Прототип отчёта для продавца** [reports/product_report.html](../reports/product_report.html): 5 товаров из
   WB-test с наибольшим числом отзывов. Для каждого — доли проблем и по 3 примера. Дат у отзывов в данных нет,
   поэтому динамики по времени нет.

## Нужен ли ответ человека

- Инструкция разметчика: [docs/needs_reply.md](../docs/needs_reply.md) — 7 причин и «ответ не нужен».
- Слабые сигналы из ответов продавцов: [reports/answer_signals.md](../reports/answer_signals.md). На 1★ продавцы
  отвечают по существу в 10.5% случаев, на 5★ — в 1.8%. На вопросы покупателей отвечают по существу в 24% ответов.
- Подготовлена исходная выборка из 500 отзывов WB-train. В [labeling/needs_reply_labels.json](../labeling/needs_reply_labels.json)
  сохранена 101 ручная метка, в том числе 9 отзывов, где нужен человек. Причины проблемы отмечаются независимо от необходимости ответа.
- LLM-учителя разметили 20 тыс. отзывов; итоговые метки использованы для обучения ruBert-base с головами
  «нужен человек», 8 причин и 4 тональности. Подробности: [метки учителей](../reports/teacher_labels.md),
  [кривая обучения](../reports/student_curve.md), [итоговый студент](../reports/student.md).
- На отложенных метках учителей: need F1 0.674, precision 0.698, recall 0.651 при пороге 0.35,
  выбранном на валидации. Это согласие с учителями, а не независимая оценка по людям.
- На 101 ручной метке при том же пороге: F1 0.48, precision 38%, recall 67%. Порог 0.85 уменьшает
  лишние срабатывания с 10 до 6, но сохраняет 3 пропуска. Он исследован на этих же 101 примерах,
  поэтому результат нельзя считать независимой проверкой выбранного порога.
- Для следующей разметки готовы [150 отобранных отзывов](../labeling/needs_reply_items_enriched.json).
  На 10 ноября ни один из них не присутствует в файле ручных меток. Подборка специально обогащена
  подозрительными случаями и не отражает естественную частоту обращений.

**Старый интерфейс `needs_reply_label.py` требует обновления перед продолжением разметки.** Он читает
`data/*.jsonl`, а актуальный эталон хранится в `labeling/*.json`; кроме того, интерфейс связывает причины
с необходимостью ответа. Сохранённые подсказки модели в новой подборке нужно скрыть при слепой разметке.

## Демо для продавца товаров для беременных

[reports/demo_maternity.json](../reports/demo_maternity.json) содержит расчёты по 4 товарам и 825 отзывам:
тональность, причины, темы, ответы продавца и кандидатов на ответ человека при пороге 0.85.
Скрипт: [scripts/demo_maternity.py](../scripts/demo_maternity.py).

Демо остаётся черновиком: разметка тем иногда путает противоположные утверждения («тянется» и «не тянется»,
«размер соответствует» и «не подошёл»), а цитаты к причинам требуют ручной проверки. Доли тем до исправления
этих ошибок нельзя подавать как проверенную аналитику. Дат отзывов в исходных данных нет.

## Запуск

```bash
pip install -r requirements.txt
python prepare_data.py   # → data/wb.parquet, data/rureviews_test.parquet, reports/data_stats.md
python finetune.py       # ученик из sentiment-analysis-ru → models/wb_student (нужна папка ../ru-review-sentiment/model)
python evaluate.py models/wb_student --name wb_student   # WB-test + RuReviews-test → reports/eval.md
bash scripts/stage2.sh   # всё вместе на GPU: дообучение, тест до/после, ONNX int8
python topics_probe.py   # проба энкодеров и кластеризации (CPU, 10k фраз) → выбор для topics.py
bash scripts/stage3.sh   # жалобы → группы → reports/topics.md → reports/product_report.html
python topics_label.py   # утвердить/объединить/выбросить группы
python needs_reply_prep.py   # исходная выборка этапа 4; старый интерфейс пока не использовать для нового эталона
```

Для воспроизведения студента с сохранёнными локальными данными используется `python train_student.py`.
Команда заново обучает модель и перезаписывает `data/student/model`, результаты и отчёт; перед экспериментом
нужно сохранить текущую версию. Инструкции и необходимые файлы перечислены в [состоянии проекта](../docs/project_status.md).
